Development 0.6.0 now verifies real OpenClaw no-tool transport through the configured local model; see [connected AI verification](CONNECTED_AI_VERIFICATION.md). Development 0.7.0 also verifies a real bound-context rejection review and blocked planning; see [real governance verification](REAL_GOVERNANCE_VERIFICATION.md). ## Workflow and contracts

Configure connections under **Settings → AI connections**. The saved quick/deep model choices also serve native research. The new OpenClaw settings select a quick/deep model independently for each route, a time budget and an output-token limit per model call. They use the existing immutable setting revisions, scope inheritance, reasons, history and restoration. Saving does not call an AI model. A private Gateway refreshes settings automatically and restarts when its routing fingerprint changes. Ready means configured services have applied that routing; actual provider access is established only by a successful run.

Create a paper proposal linked to a successful original native report for the same instrument and current UTC research date. Select **OpenClaw · Cloud AI** or **OpenClaw · External local AI** and request review. The job captures the exact proposal, unchanged native evidence, deployment, account policy/revision, attributed open positions, receipt-stamped current observation, ledger digest, route/model revision, settings and expiry. Credentials are excluded. Current native reports remain daily USD research; the explicit paper proposal is long spot in USDT. The governor must defer or reject missing or ambiguous evidence and cannot infer intraday execution from daily research.

The private review worker targets a separate `governor-cloud` or `governor-local` agent through the pinned Gateway's [HTTP interface](https://docs.openclaw.ai/gateway/openai-http-api). A job-specific conversation prevents earlier reviews from sharing context. The sole agent tool is `tauric_review_context`; it retrieves the immutable captured context through the project plugin and records that the context was retrieved. Native reports are untrusted evidence, never tool instructions. The returned job/proposal/policy IDs and context checksum must match, and only allow/reject/defer plus a bounded reason are accepted. Markdown, extra order fields, duplicate fields, malformed/incomplete responses and mismatched identities fail closed.

Successful results create separate immutable governance records with `source=openclaw`, `authority=paper_only`, pinned runtime version, model route, context checksum and reported token usage. Original reports and ratings remain unchanged. Reported usage is also retained for malformed final responses; unavailable usage stays unknown and prices are not invented. Failed HTTP calls cannot establish the provider's actual billed usage.

Only a current allow can feed the existing deterministic Decimal paper planner. Planning refreshes prices for the proposal and all held instruments. Existing risk, cash, fees, exposure, step, expiry, idempotency, attribution and reconciliation rules apply. OpenClaw has no size, fill, order, policy-write, broker, shell or messaging tool. Simulation and closes remain explicit owner actions. Stops remain sizing references, without monitoring or automatic protective exits.

## Durability and private boundary

The queue admits at most four jobs; one leased worker processes a review at a time. Lease IDs prevent an old worker finalizing another worker's job. A lost lease becomes interrupted, with no automatic queue retry. An identical request returns its prior job; changed inputs conflict. An active OpenClaw review blocks an owner review of the same proposal. The immutable decision consumes its proposal once. Account/policy/ledger, native evidence, model/credential changes, expiry or an unavailable/mismatched Gateway invalidate pending results.

Migration `0006_governance_queue` adds immutable-request jobs, guarded lifecycle writes and a private Gateway routing heartbeat. Terminal jobs cannot be edited or removed by application roles. Worker/storage failures leave an honest failure or interruption rather than planning permission.

The independently pinned OpenClaw **2026.9.7** runtime and its core are unchanged. The project owns the distinct plugin package, generated manifest, skill, workflow, config builder and bootstrap. The [tool plugin SDK](https://docs.openclaw.ai/plugins/tool-plugins) remains the extension boundary. Tool Search and Code Mode are disabled for these single-tool agents. Cron, model heartbeats, memory agent, memory flushing and cyber failover are disabled. Each agent has a single selected model and empty fallback list. There is no unattended scheduling or fallback certification in this stage.

The Gateway receives only private service tokens and model credentials through the authenticated internal configuration API, not database passwords or broker secrets. Config/state files use private permissions and the Gateway drops root privileges. Its port is not published; Caddy rejects `/internal/*`. Gateway/operator credentials are never returned to the browser. Provider/agent logs are suppressed because they may include private inputs; public failures use generic categories.

## Verification scope

Backend tests use isolated PostgreSQL databases and explicitly labelled native/model fixtures. The Gateway config is checked against the actual pinned upstream schema for both configured routes and the empty initial state. The real SDK compiles, validates and executes the two project context tools. Built-container browser tests use an internal OpenAI-compatible SSE fixture with the actual Gateway, plugin and private API. They prove transport, tool calling and validation mechanics; they do not certify a real model or provider.

Native → OpenClaw analysis requests, connected real cloud/local models, provider-specific capability certification, fallback policy, monetary budgets, autonomous scheduling, full nested capital entities, other asset/time scopes and broker execution remain pending. Provider mappings are prepared for OpenAI, Anthropic, Google, OpenRouter, Ollama and OpenAI-compatible endpoints; a schema-valid mapping is not proof of that endpoint's model/tool compatibility.

The full platform remains **not ready for server installation**. Linux amd64/IONOS measurements, install packaging, backup/restore, rollback and a 24-hour soak are still required. See [server readiness](SERVER_READINESS.md).
