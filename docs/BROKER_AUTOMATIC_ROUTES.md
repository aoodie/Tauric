# Automatic OANDA practice and Alpaca paper routes

Saved demo routes now evaluate current closed candles, calculate a quantity, queue an exact native Tauric assessment, request a separate bound OpenClaw broker review, and deliver one approved order through the existing durable broker execution worker. The workers observe actual positions and broker protection. A complete post-fill candle below the original strategy's exit channel can request an attributed close; candle stop/target touches never claim an actual broker fill.

The route risk setting starts at **1% of account equity per trade**, is adjustable, and is an estimate rather than a guaranteed maximum loss. Quantity is rounded down to broker increments. The calculation uses equity × percentage ÷ loss per unit at the observed ask and strategy stop; OANDA uses the broker's account-loss currency conversion and a distinct position-value conversion for available margin. Alpaca uses whole shares and the account's buying power. Broker limits can reduce the estimated quantity. Missing or invalid conversions, available capacity, stop geometry or minimum size block the assessment. Gaps, slippage, financing and fees can increase actual losses.

The user's no-limits preference removes additional owner capital, exposure, position-count and daily-loss caps. It does not remove an order's size calculation or broker restrictions. The old manual broker policy's `automatic_entries_enabled` field predates scheduling: an enabled owned route version supplies separate, immutable scheduling authority, pinned inside both model contexts and checked before the broker effect.

Every owned strategy version, instrument and closed-bar timestamp has one permanent signal key across route revisions and duplicate routes. An assessment, review or order is not repeated because a response was lost, a model failed, the worker restarted, the signal expired, or a broker submission became unknown. Missed check intervals coalesce into a current observation. Existing shared model queue/allowance controls bound compute resources rather than trading exposure.

Pause, route revision, broker policy/connection change, account mismatch, native model change or OpenClaw routing change blocks pending entries. Already submitted positions retain protection and original-strategy channel monitoring. Entry quantity is never silently resized after either assessment; increased stop risk or inadequate current broker capacity rejects that exact permission.

The demo worker gives discovery, workflow advancement, approved-order delivery, intent reconciliation and position reconciliation independent turns so a busy position queue cannot starve entries or signal checks. Immutable versions and event receipts, guarded workflow links, owner locks, permanent signal keys and stable request IDs preserve recovery and attribution. Historical position facts may be deduplicated; their mutable observation cursor supplies freshness and recovers from temporary unknown status.

Schema `0028_broker_routes` adds four tables. The backup/restore rehearsal in `artifacts/broker-routes-backup-verification.json` preserved all 63 pre-existing tables and created empty route tables. Focused tests cover Alpaca calculated sizing, OANDA GBP sizing through native FX REVIEW plus separate exact approval, duplicate/concurrent discovery, pause before model/review/delivery, changed equity/quotes, rejection, one-shot delivery, immutable history, actual fixture fills/closes and external-holding preservation. The built UI test covers explicit enable, a lost save response, one signal/order, pause, reload, mobile rendering and browser errors. Those are offline fixture checks, not proof of connected model approval or broker fills.

`broker_demo_routes_setup.py` creates a clearly labelled, **unqualified demo** 15-minute breakout preset: 20-bar entry window, 1.5× activity filter, prior-low stop, 2R target, 10-bar channel exit and a 900-second signal lifetime. It configures EUR/USD and AAPL on the already verified demo accounts using a configured AI connection. The preset has not been demonstrated profitable; market intelligence, qualified strategy discovery and full-release acceptance remain separate unfinished work.

References for broker currency and capacity semantics: [OANDA home conversions](https://developer.oanda.com/rest-live-v20/pricing-df/#HomeConversions), [Alpaca buying power and margin](https://docs.alpaca.markets/us/docs/margin-and-short-selling).

## Connected practice verification — 4 October 2026

One owner-authorized integration check filled 100 EUR/USD units in OANDA practice at 1.12610 (creation transaction 258, fill/trade 259). Broker-held stop 261 and target 260 were verified pending before the close. One attributed close filled at 1.12593 (order 262, transaction 263), leaving zero units with broker-reported GBP realized P&L of -0.0130. Durable receipts prove one entry submission and one close submission; neither was repeated during recovery. See `artifacts/oanda-connected-trade-receipts.json` and `artifacts/oanda-connected-filled-cycle-verification.json`.

The connected check exposed two adapter issues: filled market orders were unavailable through the order-resource lookup, and closed trades omitted unrealized P&L. Market submissions now consume their actual fill/cancel transactions directly; lost responses use bounded read-only transaction discovery by exact client ID, with saved creation IDs for older fills. Account, instrument, quantity, allocation and terminal batch bindings are verified. A missing lookup never authorizes another submission. Closed trades may omit unrealized P&L only with zero remaining units; open trades still require that amount. Reference: [OANDA transaction endpoints](https://developer.oanda.com/rest-live-v20/transaction-ep/) and [trade definitions](https://developer.oanda.com/rest-live-v20/trade-df/).

Both routes were paused during repair and resumed at revision 3 after the position and close request reconciled. The focused transaction/execution/route regression passed 118 checks; the lifecycle/position/transaction group passed 39 checks; the final lifecycle suite passed 17 checks including contradictory closed units and omitted open-trade P&L. These groups overlap. Eight backend services use the repaired broker sources. Concurrent scanner refactoring is excluded from this isolated deployment; the source verifier names the files it checks explicitly.

At the final read-only readiness check, both route guards passed in the broker and native workers, OpenClaw exposed the bound broker-review tool, OANDA had no positions, and Alpaca's pre-existing MSFT 34/NVDA 86 holdings were unchanged. OANDA's last route receipt held because breakout/activity filters did not both pass; Alpaca was blocked by its closed regular session. Quote freshness is checked on every entry, and a stale quote blocks trading. The connected integration check is separate from the automatic strategy: no primary automatic native assessment or OpenClaw review has yet completed, and the full qualifying-signal-to-approved-fill cycle remains unverified on connected accounts.
